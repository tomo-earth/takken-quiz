## 最初にやること（友寄様の手動作業）

1. `谷直美様邸_現場日報台帳_集計.xlsm` を Excel で開く
   （保護ビューの場合は「編集を有効にする」→「コンテンツの有効化」でマクロを許可）。
2. **Alt + F8 → 「印刷_ボタンを配置」を選んで「実行」**（初回のみ）。
   印刷メニューシートの G 列にボタンが 6 個並びます。以後はボタンから操作できます。
3. 動作確認:
   - 「○のシートをプレビュー」→ 印刷01〜06 の 6 シートがグループでプレビューされること
   - プレビューを閉じると、グループが解除され元のシートに戻ること
   - B 列の ○ をすべて消してからプレビュー → 「印刷するシートのB列に ○ を付けてください。」の警告が出ること

もし xlsm が開けない・「修復しますか」と出る・マクロ一覧に出ない場合は、
`フェーズ1_マクロ組み込み.ps1` の方法で作り直してください（手順はスクリプト冒頭のコメント参照）。
その場合はお手数ですが結果をお知らせください。

## この環境でできたこと・できなかったこと

この作業環境は Linux で **Excel（COM）がありません**。指針どおりならその報告と手動手順の案内のみですが、
今回は Microsoft の公開仕様（MS-OVBA / MS-CFB）どおりに `vbaProject.bin` を直接生成して
xlsx に注入する方法で **.xlsm 自体を作成済み**です。構造は Excel で実績のある
EPPlus ライブラリと同じレイアウト（参照: stdole・Office、文書モジュール ThisWorkbook + Sheet1〜13 を空で用意、
標準モジュール「印刷メニュー」に付録Aのコード）です。

実施できた検証（Excel の代わり）:

- **oletools(olevba)**: 生成した xlsm から 15 モジュールすべて認識、
  「印刷メニュー」モジュールのソースが .bas と**バイト完全一致**で取り出せる
- **olefile**: vbaProject.bin の CFB コンテナ構造を警告なしで解析
- **LibreOffice 24.2**: xlsm を正常に読み込み（全シート PDF 出力成功）、
  さらに VBA プロジェクトを解析して xlsm へ再保存しても 15 モジュール・コードが保持される
- 圧縮(MS-OVBA)・保護フィールド暗号化は自作実装を oletools の展開器・仕様の復号手順で往復検証済み

**未実施**: Excel 実機での最終確認（この環境に Excel が無いため）。上の「最初にやること」の
確認をお願いします。フォームボタンの配置もマクロ `印刷_ボタンを配置` の初回実行で行う設計です
（Excel 外から図形オブジェクトを安全に作れないため）。

## 元ブックに対する変更点（xlsm 側のみ。xlsx は無変更）

- `xl/vbaProject.bin` を追加（VBA 本体）
- Content-Types と workbook のリレーションに vbaProject を登録、
  ブックの種類をマクロ有効（macroEnabled）に変更
- `workbookPr` に `codeName="ThisWorkbook"`、各シートの `sheetPr` に `codeName="SheetN"` を追加
  （VBE のオブジェクト名。**シート名・数式・書式・印刷設定・入力規則には一切触れていません**。
  台帳の入力規則(x14 拡張)もバイト単位で保持されていることを確認済み）

## 事前チェック結果（依頼手順1: ブック構成の照合）

シート順・タブ色・列構成・E列の数式・マスターの内容（工程12/工種41/作業員7/業者21/機械13）・
印刷メニューの一覧（6〜17行、18行目「○の枚数合計」が終端、B列は○のみのリスト・エラー非表示）・
印刷設定（A4・余白 左右0.4/上下0.5・横中央・ヘッダー/フッター・fitToWidth=1）はすべて仕様書どおりでした。

仕様書と異なっていた点は 1 か所だけ（実害なし・修正不要）:

- 仕様書 2.4 では日別集計を「5〜141行が全日・**142行目が合計**」とありますが、
  実物は **5〜140行が 4/20〜9/2 の 136 日・141行目が合計** です（数式は内部で整合、印刷範囲も $A$1:$AG$141 で一致）。
  マクロはこの行番号を参照しないため影響ありません。フェーズ2-B（日付範囲の自動延長）の際に正しい行番号を使います。
